# Phase 3B3B2 — Verification Runner

This internal module runs the fixed `command-center-v1` profile in four separate verifier containers. The profile definition is shared by the host controller and the pinned runner image. The runner accepts only a snapshot fingerprint, profile ID and command ID; executable, arguments, environment, image, network, mounts and limits come from trusted files.

The runner image is built locally from the verified Phase 3B3B1 image. Its identity records the parent digest and image ID, runner/profile/bootstrap hashes, platform and final digest. The build uses the already present `cc-verifier:phase3b3b1` local tag after verifying that it points to the approved B1 image, sets `--pull=false`, disables network for build steps, and performs no dependency installation. Runtime uses the immutable final digest.

For each command, the host fingerprints the completed sanitized snapshot, verifies its approved package manifests and host checkpoint, then creates one NO_NETWORK verifier container. The image-owned runner rechecks the snapshot, prepares a private `/verify/workspace`, rechecks the source identity and launches the fixed Node argv with `shell:false`. The host verifies Docker policy before and after execution, reads the exact container ID's raw inspect result, and destroys that exact ID. The next command gets a fresh container only after cleanup is confirmed. A non-PASS result stops the profile and marks later checks `NOT_RUN`.

The source checkpoint is intentionally bounded. A process-local registry prevents Command Center managed writers from starting for the source during the run. It does not prove that arbitrary host processes are stopped or that the whole Mac is immutable. Source files, worktree Git metadata/configuration, the separate Control Plane checkout, its registered private paths and a synthetic external canary are fingerprinted. The host checks these fingerprints before each command, after each command cleanup and after the profile. Docker container, network and volume inventories must return to their initial identities.

`PASS` requires complete before/after policy readback, complete raw execution state including explicit `OOMKilled:false`, exit 0, no timeout/output limit, unchanged host and snapshot fingerprints, and confirmed container destruction. Definite, complete non-zero/timeout/OOM failures are `FAIL`; ambiguous evidence is `UNKNOWN`. Program output is diagnostic and cannot create evidence. Evidence includes identity hashes and selected raw Docker inspect fields; it never stores canary contents or credentials.

The profile is internal-only. It is not mounted in `server.ts`, browser routes or the fake-only Orchestrator. Use `node scripts/run-verification-profile.mjs --run-clean-candidate` only from the clean candidate branch. Real Claude/Codex execution remains disabled.
