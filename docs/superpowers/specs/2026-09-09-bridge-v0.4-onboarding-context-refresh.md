# Bridge V0.4 Onboarding Context Refresh

**Status:** Documentation-only refresh for review. This specification records
the verified local baseline as of 2026-09-09; it does not grant provider,
deployment, approval, or execution authority.

## Purpose

Refresh the `.bridge` onboarding documents without rewriting the historical
V0.3 onboarding design. The refreshed documents must distinguish verified,
local capabilities from dashboard values that are fixtures, browser memory,
user-entered, or AI-generated and therefore non-authoritative.

## Verified local baseline

1. The React UI can save and load local state through the loopback state API.
   `server/localStateStore.mjs` persists valid state to
   `data/app-state.json`; this is local persistence, not an approval or
   system-of-record claim.
2. The loopback GitHub router exposes repository and pull-request status
   reads. It validates loopback origins and delegates to read-only GitHub CLI
   queries; it does not approve, merge, label, or otherwise write GitHub
   state.
3. The V0.4 Command Center consumer can send a local Codex handoff through
   the Codex App Server. Its proposal phase is a read-only repository
   inspection. The route is development-only, loopback-origin constrained,
   and depends on a server-side local allowlist.

## Authority boundaries

- Dashboard project gates, suggested actions, fixture values, browser-memory
  state, user-entered content, and AI-generated content are not evidence of a
  real human approval, review, execution, or release state.
- The provider-facing AI routes remain protected. This refresh neither calls
  nor changes them.
- A workspace-write handoff, GitHub write, provider behavior, mapping change,
  approval, merge, deployment, release, billing change, or secret change is
  outside this documentation refresh and needs its own authorization.

## Document changes

- `.bridge/PROJECT_CONTEXT.md` names the current checkout and source roots,
  then separates local capabilities from non-authoritative dashboard state.
- `.bridge/ARCHITECTURE.md` records the local state, read-only GitHub, and
  local Codex handoff flows, including their controls.
- `.bridge/ENVIRONMENTS.md` identifies the local runtime as development-only
  and retains Development, UAT, and Production as unverified.
- `.bridge/BRIDGE_CONFIG.yaml` reflects the current npm commands and V0.4
  read-only proposal capability without altering machine-local mappings,
  provider settings, or secrets.

## Validation

Validate Markdown links and YAML syntax, verify that the diff only contains
these five documentation files, and run `git diff --check`. No provider route,
mapping, deployment, commit, push, or release action is part of this work.
